# План развития: полноценный справочник по экзаменам

Дата: 16 сентября 2026. Статус: план утверждается. Исполнитель и порядок — этапы в конце документа.

Кратко: углубить три действующие справки (IELTS, TOEFL, Cambridge English) до уровня «формат + баллы + соответствие CEFR + официальная практика», затем расширить каталог новыми экзаменами на той же модели, без смены стека и без нарушения URL/ID.

## Продуктовое обоснование

Сегодня раздел «Экзамены» — три карточки с фазами подготовки и одной ссылкой на официальный сайт. Пользователь с целевым экзаменом не получает из справочника:

- структуру экзамена по частям с типами заданий и временем;
- связь результата (band/балл/уровень) с CEFR;
- срок действия сертификата и условия признания;
- официальные бесплатные практики и демонстрационные тесты;
- сравнение «какой экзамен выбрать».

Это и есть ближайший работающий минимум полноценного справочника.

## Ограничения

- Экзаменационные требования и стоимость меняются. Все факты — с датой проверки (`linkCheckedAt`) и статусом `verified`/`pending`. Невыдуманное правило: что не проверено — `pending` и в карточке.
- Все внешние ссылки — только официальные источники (cambridgeenglish.org, ets.org и т. д.).
- ID и slug фиксированы. Переезд Cambridge English из одной записи в семейство — отдельный шаг с сохранением прежнего URL `/exams/cambridge`.
- Сайт остаётся статическим справочником: без записи на тесты, без результатов и без серверной логики.

## Этап A. Модель данных экзамена

Цель: одна схема, которая покрывает и единичные экзамены, и семейство Cambridge.

Поля `examGuideSchema`, которые добавляются/меняются (см. `src/data/types.ts`):

| Поле | Тип | Зачем |
|---|---|---|
| `familySlug` | `string \| null` | Связь записи с семейством: у `b2-first` будет `"cambridge"`, у IELTS — `null` |
| `levelStatus` | `'single' \| 'family'` | Отдельный экзамен или страница-семейство |
| `familyMembers` | `{ id, title, cefrLevels, slug }[]` | Список квалификаций для страницы-семейства |
| `duration` | `text` | «2 ч 45 мин» |
| `scoreScale` | `{ min, max, goodFrom, unit, note? }` | IELTS 0–9 (band 6.5+), TOEFL 0–120, Cambridge A2–C2 |
| `scoreMapping` | `{ cefr, score }[]` | Соответствие балл → CEFR по официальным таблицам |
| `validity` | `text \| null` | Срок действия сертификата («2 года», «бессрочно») |
| `registration` | `{ costNote, frequency, format, website }` | Стоимость, частота, компьютерный/бумажный, регистрация |
| `parts` | `array<{ id, title, duration, questionCount, taskTypes[], scoreShare }>` | Части с типовыми заданиями (вместо списка строк) |
| `officialMaterials` | остаётся, но ссылка фильтруется по разделу | Практика/образцы/результаты/регистрация |

Правила валидации (`src/data/validate.ts`):

- у `family` обязателен непустой `familyMembers`, у `single` — `null`;
- `scoreMapping` монотонен по баллам и покрывает все `cefrLevels` записи;
- `parts` не пуст, `id` внутри частей уникален;
- все новые URL — через существующий `officialUrlSchema`.

Требование совместимости: старый тип `ExamGuide` меняется, но `id`/`slug` трёх записей не трогаем. Тест миграции «no published ID or URL changes» (`tests/catalog.test.ts`) остаётся зелёным.

### Разделение Cambridge на квалификации

Текущая запись `cambridge-english` / `/exams/cambridge` описывает всю линейку одним форматом — это противоречит реальности (B1 Preliminary и C2 Proficiency разные). План:

1. Сделать `cambridge-english` страницей-семейством (`levelStatus: 'family'`).
2. Добавить отдельные записи: `cambridge-a2-key`, `cambridge-b1-preliminary`, `cambridge-b2-first`, `cambridge-c1-advanced`, `cambridge-c2-proficiency` (квалификации A1 `cambridge-english-singers` не включаем).
3. Старый URL `/exams/cambridge` сохранить как страницу-семейство; на неё же ведут старые ссылки и избранное.
4. После выкладки новых записей `resource-cambridge-english` и `resource-ielts-org` обновить описания, чтобы не дублировать раздел экзаменов.

## Этап B. Наполнение трёх существующих экзаменов

Для каждой записи заполнить поля этапа A и выставить `verified` только после фактической проверки по официальным страницам:

**IELTS**
- части Reading/Writing/Listening/Speaking: время, число заданий, доля в результате;
- шкала 0–9, «band descriptors», целевые band 6.0–7.5 для вузов;
- Official Cambridge Practice Tests, официальные руководства;
- версии Academic/General Training пояснить.

**TOEFL iBT**
- части, время, шкала 0–120, пороги вузов (обычно 80–100);
- весь экзамен/части на компьютере, домашняя версия Home Edition;
- официальный набор ETS Free Practice Tests.

**Cambridge English (семейство)**
- карточка семейства B1–C2 с соответствием «квалификация → CEFR → балл шкалы/A2–C2»;
- у каждой квалификации: формат, время, типы заданий, официальные sample tests и Results Service.

Критерий этапа: у каждого экзамена на странице есть части с заданиями и временем, шкала баллов, соответствие CEFR, срок действия сертификата, стоимость и ссылки на официальные материалы; у всех фактов проставлены `linkCheckedAt`.

## Этап C. Новые экзамены в той же модели

Порядок — по востребованности среди русскоязычных учащихся и доступности официальных источников:

1. **PTE Academic** (Pearson) — компьютерный, быстрые результаты; хорошая замена IELTS для вузов.
2. **Duolingo English Test** — дешёвый и быстрый онлайн-тест; растущая база принятия вузами.
3. **Cambridge сдаётся в отдельных записях** (уже в этапе A/B).
4. **TOEIC** (ETS, Listening & Reading) — рабочий корпоративный контекст.
5. **OET** (Occupational English Test) — медицина; только если подтверждён интерес.
6. **Aptis** (British Council) — корпоративный, дешевле IELTS; страница минимум.

Для каждой: `officialUrl` на официальный сайт экзамена, `parts` по официальным материалам, `scoreMapping`, `validity`, `registration`. Каталог пополняем только проверенными записями (`reviewStatus` до проверки — `pending`).

Критерий этапа: новые экзамены появляются в `/exams`, поиске и фильтрах без правки компонентов — только за счёт данных.

## Этап D. Страницы и интерфейс

### `/exams` (список)

- Сетка карточек: краткие теги, CEFR-диапазон, тип (единый/семейство), счёт/шкала.
- Быстрый фильтр «Что сдаёте: учёба / иммиграция / работа / онлайн» — если категории данных это оправдывают.

### `/exams/[slug]` (детальная)

Новая структура (см. текущую `src/app/exams/[exam]/page.tsx`):

- шапка: название, официальное имя, организация, CEFR-диапазон, статус проверки;
- «Результат и срок действия»: шкала, целевые значения, связь с CEFR, срок действия;
- «Формат»: части → время → задания → доля результата (таблица);
- «Регистрация и стоимость»: цены, частота, формат, официальная страница регистрации;
- «Логика подготовки»: существующие фазы + подбор из планов CEFR;
- «Официальные материалы»: сгруппированы (образцы, практика, результаты, регистрация);
- связь с ресурсами каталога, где уместно (например, IELTS → `resource-ielts-org`).

### Сравнение экзаменов

- Отдельный маршрут `/exams/compare?set=ielts,toefl,pte` с таблицей: цель, формат, шкала, CEFR, срок действия, стоимость, где сдают.
- Минимум: сравнение 2–3 экзаменов; без сравнения у нас нет ответа на путь пользователя «какой экзамен выбрать».

### Поиск и фильтры

- `search.ts`: документ для экзамена влючает названия частей, организацию, шкалу, цели (tags);
- прокатки/Filters (`catalog-filters.ts`): фильтр по экзамену в ресурсах, чтобы каталог ресурсов отвечал на «материалы для IELTS»;
- избранное: детальные страницы экзаменов участвуют без изменений модели (`favoriteId` по `id`).

Критерий: все экзаменационные маршруты экспортируются в статическом режиме, search-тесты зелёные, `/exams/compare` статичен.

## Этап E. Редакция интерфейсного текста («реплики»)

Задача: русскоязычный текст на сайте звучит неестественно и канцелярско. Типичные примеры из кодовой базы:

| Текущий текст | Где | Проблема |
|---|---|---|
| «Найдите следующий шаг в английском» | главная, h1 | безличный повелительный, лучше конкретнее |
| `CATALOGUE`, `RESOURCES`, `EXAM GUIDES` | eyebrow на русских страницах | английские служебные слова поверх русского текста |
| «Найдено: 12» | каталоги/поиск | канцелярский счёт |
| «Сохранено: 3» | избранное | то же |
| «Сведения ожидают редакционной проверки.» | все карточки деталей | обезличенно |
| «Необходимость регистрации уточняется» | карточка материала | канцелярит |
| «Подходящие уровни уточняются.» | ресурс | канцелярит |
| «Сверьте его с уровнем и задачей, прежде чем строить программу вокруг него.» | главная, блок CTA | сложно, канцелярщина |
| «Кураторский каталог. Мы не размещаем копии книг…» | /textbooks | слово «кураторский» спорно, предложения длинные |

### Принципы тона

1. **Один смысл — одна короткая фраза.** Вопрос от первого/второго лица вместо канцелярского оборота: «Нашли учебник?» вместо «Учебник уже выбран?».
2. **Русский служебный язык.** Eyebrow-метки (`CATALOGUE`, `RESOURCES`, `EXAM GUIDES`) переводить: «Каталог учебников», «Каталог ресурсов», «Справки по экзаменам» — либо убирать вовсе.
3. **Числа через речевой оборот.** «Найдено 12 материалов» вместо «Найдено: 12»; в избранном — «В избранном: 3» без разрыва двоеточием, если это выглядит лучше.
4. **Проверка — глагол, а не существительное.** «Проверено 12 сентября 2026» / «Проверка не завершена» вместо «Сведения ожидают редакционной проверки».
5. **Один тезаурус.** Названия категорий чинить на одну пару «Аудирование»/«Практика» (сейчас разнобой «Слушание»/«Тренировки» из аудита) — вынести словарь в `src/lib` или `src/data`.
6. **Без превосходной самооценки.** «Проверенные материалы» — только там, где это подтверждено статусом `verified`.

### Механика

- Инвентаризировать все строки: греп по `src/` (компоненты, страницы, данные, `validate.ts`) и тесты — стреп-ветки русских строк в шаблонах.
- Опционально: собрать строки в `src/lib/copy.ts` с типизированными ключами, чтобы правка была централизованной и не разваливала тесты на поиск/фильтры (они проверяют тексты пользователей, а не UI).
- Переписать главную, каталоги, детальные страницы, пустые состояния, статусы проверки.
- Прогнать `bun test`, `bunx tsc --noEmit`, `bun run lint`, `bun run build`; визуально пройти 5 пользовательских путей из ROADMAP.

Соответствие встроенному критерию качества: правки строк не меняют `id`/`slug`, не ломают маршруты и тесты.

## Порядок и критерии

Рекомендуемый порядок: **A → B → D(exams) → C → E**. C зависит от A и B (нужна готовая модель и эталон заполненной записи). E независим и может выполняться параллельно.

Проверочные точки:
1. Модель A собрана, старые 3 записи валидны, миграционные тесты зелёные.
2. IELTS/TOEFL/Cambridge-family наполнены (этап B), страницы показывают шкалу, формат, срок действия, стоимость, официальные материалы.
3. Новые экзамены добавляются только данными (этап C), карточка не требует правки компонента.
4. Страница сравнения `/exams/compare` статична и работает в Pages-экспорте.
5. Весь UI-текст приведён к принципам тона (этап E), греп не находит старых формулировок, разнобой категорий устранён.
